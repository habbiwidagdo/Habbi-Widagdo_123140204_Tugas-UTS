Pada baris kode tersebut adalah untuk memanggil library standar python. Koe pada blok ini akan berjalan jika Kita mengeksekusi file ini langsung dari app.py. Baris kode ini tidak akan berjalan jika file ini diimpor dari file Python lain.

with Configurator() as config: (pada baris 12-14)
Bagian baris kode ini merupakan terpenting dari Pyramid. Pada bagian ini kita mendaftarkan semua bagian: rute URL, fungsi view, pengaturan keamanan, dll. Disini, kita melakukan dua hal:
1. config.add_route('hello', '/'): Membuat aturan bernama 'hello' yang cocok dengan URL / (halaman root).
2. config.add_view(hello_world, route_name='hello'): Memberi tahu Pyramid, "Jika rute 'hello' dipanggil, jalankan fungsi hello_world."

def hello_world(request): (pada baris 6-8)
Ini adalah fungsi View. Ini adalah kode kita yang sebenarnya, yang menerima permintaan (request) dan mengembalikan respons (response). Misalnya mengambil data dari database dan menghitung sesuatu akan hidup di sini.

serve(app, ...): (pada baris 15-17)
Ini adalah Server. Setelah aplikasi selesai "dirakit" (app = config.make_wsgi_app()), waitress (server HTTP) mengambil alih. Tugasnya adalah "mendengarkan" di port 6543 untuk permintaan yang masuk dari browser dan meneruskannya ke aplikasi Pyramid.

Tugas Tambahan
1. Kenapa menggunakan print('Incoming request'), tapi tidak print 'Incoming request'. Hal itu karena sintaks yang benar untuk Python 3 dengan menggunakan tanda kurung, sedangkan Python 2 tidak perlu menggunakan tanda kurung.
2. Yang akan terjadi jika menggunakan string HTML adalah Pyramid akan memberikan peringatan karena view tidak mengembalikan objek repons WSGI yang valid. Hal tersebut membuktikan bahwa view harus mengembalikan objek Response bukan hanya string biasa. Yang terjadi jika mengembalikan urutan integer adalah akan mendapatkan error, karena list bukanlah obejk respons yang valid.
3. Memasukkan kode yang invalid dalam fungsi hello_world akan menghasilkan app.py yang berhasil di run tanpa error. Perbedaan antara syntax error (seperti print '...') dan runtime error (seperti print(xyz)) menjadi jelas. Aplikasi bisa dimulai karena sintaksnya valid, tetapi crash saat mencoba menjalankan logika yang rusak di dalam view. Eksperimen ini menyoroti pentingnya terminal bagi pengembang web. Browser hanya memberi tahu kita bahwa "ada sesuatu yang salah" (Internal Server Error), tetapi terminal memberi tahu kita dengan tepat apa yang salah, di mana letak kesalahannya (nama file dan nomor baris), dan mengapa itu salah (NameError).
4. Ini adalah sebuah standar atau "jembatan" teknis dalam Python. Tujuannya adalah mendefinisikan cara standar bagi server web untuk berkomunikasi dengan aplikasi web. Standar ini sangat penting karena memisahkan tugas: pengembang server fokus membuat server yang cepat dan efisien, sementara pengembang framework fokus membuat alat yang mudah digunakan. Selama keduanya mematuhi standar WSGI, mereka dapat "berbicara" satu sama lain. Standar ini dimodelkan setelah CGI (Common Gateway Interface), yang merupakan standar yang lebih tua dan lebih lambat untuk fungsionalitas serupa.
